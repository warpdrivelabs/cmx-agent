# 飞书 IM 对话端到端实现 —— 完整逻辑

> 日期：2026-09-08 · 状态：✅ 真机跑通（飞书发消息 → 界面实时显示 → 飞书收到回复，两端一致）
>
> 本文记录飞书对话从「IM 收消息」到「界面显示 + 飞书回复」的**完整链路**与关键设计，含实时展示通道
> 与两端一致性。IM 抽象已就位，微信/钉钉接入走同一条路。

## 一、目标

飞书发一条消息 →
1. 桌面壳对话界面**实时显示**这条消息 + agent 回复；
2. 飞书也**收到**回复；
3. 出错时，飞书和界面显示**同一份**错误文案（两端一致）。

且这条链路 **IM 无关**：微信/钉钉接入只需新写 provider，零额外改动。

## 二、整体架构

```
飞书 ──ws──▶ FeishuProvider(Stream task) ──▶ inbox 队列
                                                  │ poll
                                                  ▼
                                         ImBridge.tick
                                          (白名单鉴权)
                                                  │
                                                  ▼
              ┌──────────────────────── AgentApp::send(im-feishu-<chat>, text)
              │                                    │ (跑回合：五层守卫 + 工具)
              │                                    │
              ▼                                    ▼
   事件落 SessionEventBus          回合结束 → chunk_text 分段
              │                                    │
              ▼                                    ▼
   壳层 setup task                  ImBridge → provider.send → 飞书回发
   emit("session_event", env)
              │
              ▼
   前端 listen("session_event")
   → onSessionEvent 分流渲染
```

一个进程同时跑：桌面 UI + IM 桥，**共用同一个 `Arc<AgentApp>`**。IM 消息跑同一回合循环，
事件经总线实时推前端，回复经桥回发 IM。

## 三、分层与文件

| 层 | 文件 | 职责 |
|---|---|---|
| IM provider | `crates/cmx-agent-im/src/feishu.rs` | 飞书 Stream 长连接（收消息 + 发消息） |
| IM 桥 | `crates/cmx-agent-im/src/lib.rs` | `ImProvider` trait + `ImBridge` 编排（transport 无关） |
| IM 配置 | `crates/cmx-agent-im/src/config.rs` | `ImConfig` 收口（provider 选择 + 白名单 + 凭证） |
| 事件总线 | `crates/cmx-agent-app/src/bus.rs` | `SessionEventBus` + `BusSink`（IM 无关 pub/sub） |
| 应用核 | `crates/cmx-agent-app/src/app.rs` | `AgentApp::send_inner`（回合 + 落库 + 出错一致性） |
| 桌面壳 | `crates/cmx-agent-shell/src-tauri/src/main.rs` | 装配 IM 桥 + 总线转发 task |
| 前端 | `crates/cmx-agent-shell/src-tauri/ui/index.html` | 监听 `session_event` + 分流渲染 |

## 四、各层实现

### 4.1 飞书 Provider（Stream 长连接）

`FeishuProvider`（`feishu.rs`）—— agent 主动连飞书 websocket 拉消息，**无需公网回调 URL、零 AES/SHA crypto 依赖**。

- **拿连接地址**：`POST {base}/callback/ws/endpoint`，body `{AppID, AppSecret}` → `data.URL`（wss）。
- **建连**：tokio-tungstenite + rustls 连 wss。
- **帧**：protobuf `Frame`（pbbp2.proto），**手写编解码免 prost 依赖**。`method=0` 控制（ping/pong），
  `method=1` 数据（event）。headers 含 `type=event|ping|pong`、`message_id`、`seq`。
- **心跳**：客户端 30s 发 ping，服务端回 pong。
- **收消息**：`type=event` 数据帧，payload 为 v2 事件 JSON（`im.message.receive_v1`），取
  `event.message.{chat_id, content}` → content 解出 `text`。回 ack 数据帧（`{"code":200}`）。
- **发消息**：`POST {base}/open-apis/im/v1/messages?receive_id_type=chat_id`，Bearer
  `tenant_access_token`（由 `auth/v3/tenant_access_token/internal` 换取并缓存，过期前 60s 刷新）。

内部状态全 `Arc`（`FeishuInner`）：`inbox: Mutex<VecDeque<InboundMsg>>`、`seq: AtomicI64`、
`token: Mutex<Option<(String, Instant)>>`、`started: AtomicBool`。

`run_stream_loop`：失败/断开 → 3s 退避重连，永不放弃。

`impl ImProvider`：
- `poll(offset)`：从 inbox drain，只取 `update_id > offset`，丢弃已过游标的（防崩溃重启重复驱动）。
- `send(chat_id, text)`：调发消息 API。
- `start()`：CAS 守门，仅首次 spawn Stream 后台 task。

协议解析/帧构造提成纯函数单测：`parse_receive_event` / `build_send_body` / `encode_frame` /
`decode_frame` / `make_ping/pong/ack_frame`。

### 4.2 IM 桥（transport 无关）

`ImProvider` trait（`lib.rs`）：
```rust
async fn poll(&self, offset: i64) -> Result<(Vec<InboundMsg>, i64), String>;
async fn send(&self, chat_id: &str, text: &str) -> Result<(), String>;
async fn start(&self) -> Result<(), String> { Ok(()) }   // 默认 no-op
```

`ImBridge`：
- 每个 IM 会话 → 稳定 agent 会话 id `im-<kind>-<chat>`（前缀防多 provider 撞名）。
- `tick()`：`poll` → 白名单鉴权 → `app.create_session` → `app.send(sid, text)` 跑回合 →
  `chunk_text` 分段（3800 字符，优先换行断）→ `provider.send` 回发。
- `run()`：主循环，无消息节流 500ms，出错退避 3s。

### 4.3 配置收口

`ImConfig`（`config.rs`）：
- `ImKind { Telegram, Feishu }` + `label()`（会话前缀）。
- `from_env()`：解析 `CMX_AGENT_IM_KIND`、白名单。
- `build_provider()`：按类型装配 `Arc<dyn ImProvider>`。
- 白名单：`CMX_AGENT_IM_ALLOW` 逗号分隔 chat_id；`CMX_AGENT_IM_NO_ALLOW=1` 显式放开（仅测试/内网）；
  两者都未设 → **拒裸奔**（Err）。

### 4.4 会话事件总线（IM 无关 pub/sub）

`SessionEventBus`（`bus.rs`）：包 `tokio::broadcast`，容量 1024。
- `subscribe()` → receiver；`publish(env)` → 广播。
- `BusSink`：挂到 `SessionLog::add_sink`，把该会话每个 append 的事件封装成
  `EventEnvelope { session_id, event }` 广播到总线。

`AgentApp::send_inner`（`app.rs`）**每个回合无条件挂 BusSink**：
```rust
session.log.add_sink(Arc::new(BusSink::new(session_id, event_bus.sender())));
```
→ 任意来源（本地 / IM 桥）的本回合事件都广播给所有订阅者。`AgentApp::event_bus()` 暴露总线引用。

### 4.5 出错一致性（飞书 ↔ 界面）

`send_inner` 不再用 `?` 抛 `run_turn` 错误，改为捕获：
- 把错误文案作为 `EventKind::Note { text }` 追加（经 BusSink 广播给界面 + 落库）。
- 补一条 `TurnEnded { reason: Error }`。
- 错误文案塞进 `final_text` → `ImBridge` 据此回发飞书。

→ 飞书和界面拿到**同一份**错误文案（Note 事件），两端一致。

### 4.6 桌面壳装配（IM 桥 + 总线转发）

`main.rs`：
1. **`start_im_if_configured(rt, app)`**：读 `CMX_AGENT_IM_*` env，配了就装配 `ImConfig` →
   `provider.start()`（飞书起 Stream task）+ `ImBridge::new(app, provider, label, allow).run()`
   在 `net_rt` 上常驻。与桌面 UI **共用同一个 `Arc<AgentApp>`**。
   - 未配 env（如无白名单）→ 静默跳过，不打扰纯本地用户。
   - 装配失败 → 仅打日志，不阻断 UI（IM 是可选通道）。
2. **`.setup()` 常驻转发 task**：`app.event_bus().subscribe()` → `while rx.recv() → handle.emit("session_event", env)`。
3. **tracing 初始化**：`tracing_subscriber` + `EnvFilter`（RUST_LOG），IM 连接/未授权 chat_id 靠它打到 stderr。

### 4.7 前端实时展示

`index.html`：
1. **全局监听**：`listen("session_event", e => onSessionEvent(e.payload))`。
2. **`STREAMING = new Set()`**：本地流式中的 session id。`streamSend` 开始时 add、`finally` delete。
   全局监听里 `STREAMING.has(sid)` → 跳过（交给本地 `send_stream` 流式通道，避免双重渲染）。
   IM 会话永不在 STREAMING → 走 session_event 实时通道。
3. **`onSessionEvent(env)`**：
   - tab 不存在 → `openSessionLive(sid)` **同步建 tab + log**，本条立即 `renderEvent`；
     后台 `get_events` 补历史时 **prepend**（不 `innerHTML=""` 擦除），用 `log._seqs` 去重。
   - tab 存在 → `renderEvent`，`log._seqs` 去重防历史与实时重复。
   - 渲染 user_message 时**无视 `_skipUser`**（那是本地乐观渲染专用标志，残留会误吞 IM 首条消息）。
   - 始终节流（400ms）`refreshTasks()`（新 IM 会话进列表 / 更新排序）。
4. **`renderEvent`** 加 `note` 分支：渲染成注记行（出错时显示错误文案，与飞书一致）。

### 4.8 调试手段
- 后端 emit 日志：`[bus] emit session_event session=... kind=...`。
- 前端 console：`[session_event] 监听已注册` / `[session_event] recv ...`。

③ 应用已发布且可用（改权限/事件后须重新发布）；④ 添加机器人能力。

## 七、抽象层评估（IM 无关的保证）

| 层 | 抽象 | 微信/钉钉接入成本 |
|---|---|---|
| provider | `ImProvider` trait（poll/send/start） | 新写一个 `impl ImProvider` |
| 桥 | `ImBridge`（transport 无关） | **零改** |
| 事件总线 | `SessionEventBus`（来源无关） | **零改** |
| 壳转发 | `session_event` 通道（provider 无关） | **零改** |
| 前端 | 按 `session_id` 前缀分流 | **零改**（新前缀 `im-wecom-`/`im-dingtalk-` 自动识别） |

加微信/钉钉只需：① 新建 `wecom.rs`/`dingtalk.rs`，`impl ImProvider`；② `ImKind` 加变体 + `build_provider` 加分支。
若该 IM 支持 Stream/websocket → 零 crypto，套 `FeishuProvider` 的后台 task + inbox 模式；
若只有 webhook → provider 内部起轻量 HTTP 收器 + 验签解密 + 队列，`poll` 从队列取（桥仍只调 poll/send）。

## 八、踩过的坑（供后续排查参考）

1. **桌面壳没起 IM 桥**：最初 IM 桥只在 CLI `im` 模式启动，桌面壳没装配 → 飞书消息没人收。
   修：`start_im_if_configured` 在桌面壳内装配。
2. **tracing 没初始化**：shell 没引 `tracing-subscriber`，IM 的 info/warn 全丢 → 抓不到 chat_id。
   修：main.rs 加 subscriber 初始化。
3. **首条消息不显示（竞态）**：`onSessionEvent` 调 async `openSession`，其 `get_events` 返回后
   `log.innerHTML=""` 重画，擦掉了并发到达的实时事件。修：`openSessionLive` 同步建 tab，
   后台 get_events 改 prepend + seq 去重。
4. **`_skipUser` 残留吞首条**：本地乐观渲染标志跨回合残留，误吞 IM 的 user_message。修：
   session_event 通道和历史回放渲染时无视 `_skipUser`。
5. **出错两端不一致**：`run_turn` 错误用 `?` 抛出，事件不落库不广播，只有飞书收到错误。修：
   捕获错误 → Note 事件广播 + 落库 + final_text 回发。
